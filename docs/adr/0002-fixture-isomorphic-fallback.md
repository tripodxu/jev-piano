# ADR-0002: fixture 与真实 Jev 同构兜底

- **状态**：接受 · **日期**：2026-09-28
- **背景**：无 API key、CORS 拦截、断网、超时——任何一条真实路径失败都不能让演奏中断（"播放永不中断"是产品红线）；同时零成本可玩是拉新关键。
- **决策**：内置**种子随机决策器 fixture**——与真实 Jev **共用同一候选集与同一权重**（权重挂在问题的 `_fixture` 字段，发送前由 `stripPrivate` 剥离）。真实 API 任何失败 → fixture 无缝接管，UI 标注"离线随机/兜底"。
- **理由**：
  1. 同构 = 离线体验与在线体验是"同一个决策器的两种采样"，不是两套产品；
  2. 确定性（`mulberry32` 种子）→ 可单测、可复现、可回归；
  3. 零成本：无 key 用户 $0；
  4. jevthoven 的 fixture provider 模式已验证此路线。
- **被否决的方案**：
  - *失败即报错停止*：破坏"永不中断"，否决。
  - *独立的启发式 mock*（与真实候选不同的简化逻辑）：听感与在线模式割裂，且双重维护，否决——fixture 必须同构。
- **后果**：改候选权重时**必须同时改 fixture 权重**（AGENTS.md 红线六）；fixture 的行为成为在线模式的行为下界保障。
