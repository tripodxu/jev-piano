# ADR-0001: 模型只做选择，代码只做渲染

- **状态**：接受 · **日期**：2026-09-28
- **背景**：让 LLM/模型"直接写音符"（输出 MIDI 或音符序列）的路线存在四个问题：非法和声无法避免、成本高（输出 token 计费）、延迟不可控、同一 prompt 不可复现。
- **决策**：**"模型选、代码写"**（jevthoven 模式）。乐理内核（`music.js`）按曲风/调式/进行池生成有限候选集；Jev 每小节一次请求、6 问并行，只在候选集里做 Choice/Noul/Score；确定性渲染内核（`composer.js`）把每个选择渲染成 NoteEvent。
- **理由**：
  1. 非法和声**不可表示**（候选集由乐理生成，模型够不着错误答案）；
  2. 成本可控：输入 ~1100 token/小节 ≈ $0.00005，输出免费；
  3. 延迟可控：单次请求 0.4–2s，被"提前 2 小节"管线藏住；
  4. 可复现：同 seed + 同候选集 = 同结果（fixture 与真实 Jev 同构）；
  5. 每个音符可溯源到一条决策——这是产品核心卖点。
- **被否决的方案**：
  - *模型直接生成音符序列/MIDI*：非法和声、计费、不可复现，否决。
  - *纯代码作曲（无模型）*：可玩但无"现场决策"叙事，且无法响应 director_note/自然语言修改，否决为 fixture 定位（见 ADR-0002）。
- **后果**：模型职责收敛为"选择"，代码职责收敛为"渲染"；新增音乐维度时 = 新增一类候选集 + 一个新问题，而非改 prompt 工程。
