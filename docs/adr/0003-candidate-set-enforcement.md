# ADR-0003: 候选集强制——答案不在候选内一律拒绝

- **状态**：接受 · **日期**：2026-09-28（13:51 反重复大修中经真实 Jev 验证强化）
- **背景**：真实 Jev 并不"守规矩"——实测出现过：① 用问题标签本身（如 `"chord"`）作为答案；② 报一个刚被根音疲劳断路器排除的和弦来"表达意图"。若照单全收，非法和弦会进入渲染层，和声安全崩溃。
- **决策**：**候选集强制**——模型答案不在候选集内（含标签作答、报被排除和弦）一律拒绝，回落最高权重候选。渲染内核永远收到合法选择。
- **理由**：
  1. ADR-0001 的"非法着法不可表示"在**发送侧**由候选集保证，在**接收侧**由本决策保证——两侧合起来才是完整闭环；
  2. 已实测的模型行为证明这不是防御性代码，而是必需代码；
  3. 回落最高权重候选 = 最保守的合法决策，不中断、不难听。
- **被否决的方案**：
  - *模糊匹配/纠错后接受*（如把 `"chord"` 猜成某个和弦）：把不确定性藏进渲染层，违背透明性，否决。
  - *报错重问*：延迟翻倍且可能再犯，否决（回落零成本）。
- **后果**：decision 元信息应能表达"发生了回落"（便于 UI 归因）；反重复机制（疲劳断路器等）因此可以放心地动态剔除候选——剔除即强制，不担心模型抗议。
