# 结构与「无声的越线」：ui.js 拆出 canvas.js，全部文件回到 ADR-0004 的 800 行以内（轮次 52 · 重构） · 2026-10-18

> **一条写进 ADR 的约束，如果没有任何东西盯着它，它就只是某次会话的意图。**
> ADR-0004 写着「每个文件 ≤800 行」，而 `ui.js` 已经长到 **842 行**、`studio.js` 811 行
> —— 越线那天没有构建失败、没有测试报红、没有任何人被告知。

## 做了什么

### 1. 先量完了渲染层，确认「性能方向」已经没肉了（这决定了本轮做什么）

轮次 51 把静止画布的重绘与逐帧布局读取都拆掉之后，用页面内 instrumentation 逐函数计时（实时演奏 15.5s）：

| 函数 | 调用 | 每秒占用主线程 | 单次 |
|---|---|---|---|
| `Fall.draw` | 453 次 | **1.79 ms/s** | 61 µs |
| `audio.play` | 66 次 | **0.73 ms/s** | 173 µs |
| `TensionGraph.draw` | 13 次（每小节一次） | 0.06 ms/s | 69 µs |
| `MotifCard.draw` | 3 次 | 0.01 ms/s | 67 µs |

合计约 **0.16 ms/s ≈ 单核的 0.016%**。另外三个「看起来该优化」的点也量了：

- **冷启动音频初始化 172 ms**，其中生成式混响 IR 只占 **4.6 ms**（其余是 AudioContext 建立/resume）—— 优化 IR 没有意义；
- **工作室卷帘 hover 重绘平均 0.69 ms、最差 3.7 ms**（32 小节 375 音）—— 已经够快；
- 6 秒内 **0 个 long task**。

**结论：前端没有剩余的低垂果实，继续在这里抠 CPU 是给自己找活干。** 于是本轮转向真正在腐化的东西——结构。

### 2. `ui.js` 842 → **447**，新增 `public/js/canvas.js` **413**

搬出去的是**有明确边界的整体**：canvas 可视化三件套 + 它们专用的纯辅助。

- `Fall`（下落音符）、`TensionGraph`（张力对照带）、`MotifCard`（动机卡）；
- `motifShape` / `pulseActive` / `MOTIF_PULSE_MS` / `sectionLabel` / `chorusView` / `hoverBarAt` / `LOW`·`HIGH`。

**新模块零 import**——它只画，不决策、不取数。依赖方向只有一条：`ui.js → canvas.js`（反向 import 会成环）。

**对外契约一格未动**：`ui.js` 对这些符号**只做转出**（`export { … } from './canvas.js'`），
`main.js` / `studio.js` / 测试的 import 路径与绑定都不变。新增一条测试断言
**`ui.js` 转出的符号必须与 `canvas.js` 是同一个绑定**（`assert.equal(ui.Fall, cv.Fall)`）——
拆分若被后人复制回去，这条会立刻红。

### 3. `studio.js` 811 → **792**：把两个纯函数送回它们本来该在的层

- `nonChordIds(piece)`（非和弦音 id，卷帘亮边）与 `findNoteAt(notes, beat, pitch)`（卷帘命中查询）
  移入 `studio-core.js`（229 → **263**）——它本来就自称「时间轴分析」的地盘；
- `studio.js` 只留**缓存门面**（`nctCache` 是界面层状态，随编辑作废，不该跟着纯函数走）；
- 顺手删掉 `studio.js` 里**未被使用的 `barTension` 导入**（纯函数层的活口，界面层不再需要）；
- 搬家时做了一处硬化：老 `nonChordIds` 直接 `piece.notes.filter`，**缺字段会抛**；现在降级为空集，有测试锁住。

## 为什么（与被否决的做法）

- **被否决：不动结构，继续找性能**。已量完（上表）：渲染层合计占单核 0.016%，再优化是自娱。
- **被否决：为了行数硬拆 `studio.js` 的播放闭包**。`startPlay/tickPlay/drawPlayhead` 与 `rp`/`els`/`loop`/`kb` 深度耦合，
  为 11 行去碰**回放**（红线「播放永不中断」）不值当——改用了「把纯函数送回纯函数层」这条零风险的路。
- **没有写 ADR**：ADR-0004 已经写着「每个文件 ≤800 行」，本轮是**回到它**，不是改变它。
  变更的是维护信号（AGENTS.md §2 加了一句提前量规则），不是架构决策。

## 坑

1. **第一次拆分把 `Fall` 切少了三行**——我按**修改前**读到的行号写死切点，而轮次 51 刚给 `Fall` 加过 3 行，
   于是 `canvas.js` 里 `Fall` 少了收尾的 `}` 与 `destroy()`，`node --check` 报
   `Unexpected token 'export'`（真实原因是括号没闭合）。**修法：切点不用行号，用内容标记**
   （`^export class Fall \{` → 向下第一个 `^}`），并对所有块做**重叠校验**。行号是快照，内容才是事实。
2. **改完要重跑 `git checkout` 才能重来**——第一次的产物已经写脏了工作区，直接覆盖不如先还原。
3. **`node --check` 对 ESM 的错误位置会指向"下一个顶层声明"**，别被它指的行号带偏；
   `import` 的符号对不上时，`node` 会在**链接期**报 `does not provide an export named`——那是比语法错误更值钱的信号。
4. **`LOW`/`HIGH` 从 `ui.js` 搬到 `canvas.js` 后必须 `export`**：`ui.js` 的 `renderKeyboard` 仍要用它们。
   搬运时容易只想着「搬走的类」，忘掉**共享常量**也要跟着有出口。
5. **本项目的 `git commit` 因为 `commit.gpgsign=true` 会永久挂住**（等 GPG 口令，无交互界面）。
   必须 `git -c commit.gpgsign=false commit --no-gpg-sign`。第一次 `git commit` 直接把 120s 的 run 时限耗尽了。
