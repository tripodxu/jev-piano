# 2026-09-28 · 动机发展真正落地（迭代轮次 11 · 创意）

> 计划：[../superpowers/plans/2026-09-28-motif-development.md](../superpowers/plans/2026-09-28-motif-development.md)

## 起因

轮次 10 让段落首「承袭」，我怀疑承袭的只有旋律、和声是随机的。量的结果**比怀疑更糟，而且方向相反**：

| 指标（12 种子，承袭小节 70 个） | 改前 |
|---|---|
| 旋律与动机音程序列**完全相同** | 2/70 = **2.9%** |
| 旋律形状接近（音程差≤1） | 2.9% |
| **平均音程差** | **3.76 半音**（约小三度——轮廓毫无关系） |

**「承袭」根本没在承袭任何东西。** 根因一行：

```js
const usePrev = !breathe && !!this.prevMelody && (dev === 'sequence' || dev === 'inversion');
```

- **`repeat` 不在这个列表里** → 选「承袭」时走 `renderMelody`，与选「新句」**完全同一条路径**。
- `sequence`/`inversion` 作用在 `this.prevMelody`（上一小节），不是动机。
- `this.motif` 只存了 `{rhythmId, contourId, pattern}`——**只有节奏，没有旋律素材**，根本无法「重述」。

这是第 1 轮「死参数」那一类缺陷的放大版：README 承诺的「动机统一」在渲染层从未实现。

## 做了什么

- 动机扩展为同时保存**旋律素材**（`midis` + `onsets`）。
- 新增 `buildFromMotif()`：从动机素材构建旋律，强拍锚到当前和弦，但**本来就在和弦里的音不动**（没必要为「合规」改掉轮廓）。
- 五种手法的素材来源**分工**（这是本轮最重要的设计判断，见下）。
- `state.motif` 改为向模型描述动机本身（音程序列 + 节奏 + 走向），`develop` 问的 instructions 改写为解释五种手法各自与动机的关系。
- 测试 104 → **105**。

## 关键设计判断：素材来源的分工

我第一版把四种手法**全部**改到动机上。隔离实验给出了明确答案：

| 配置 | 32 小节旋律种类数 | 承袭音程差 |
|---|---|---|
| 全部作用于动机 | 23.67 | 1.69 |
| 只有 `repeat` 作用于动机 | **26.92** | 2.00 |

所以最终分工是：

| 手法 | 素材 | 理由 |
|---|---|---|
| `repeat` 承袭 | **动机** | 它承载主题身份 |
| `sequence` 模进 | 上一小节 | 字面意思就是「对刚才那句做模进」 |
| `inversion` 倒影 | 上一小节 | 同上 |
| `ornament` 装饰 | 上一小节 + 经过音 | 作曲里的装饰是装饰**当前乐句**（颤音、邻音围绕），不是把主题装饰一遍 |

## 反思

- **我把累加器写成了数组**，`acc[0]` 从未赋值 → `RH NaN`。原来的 `buildFromPrev` 用的是**标量**累加器。改写别人代码时最容易丢掉这种「不起眼但关键」的实现细节。
- **我的测试判据也错了两次**：① 用「音程完全一致 ≥80%」——但和弦锚定**本来就会改变音程**，「同一想法、新的和声」正是这个意思，诚实的判据是轮廓相似度；② 用 4 颗种子的**小样本均值**——被单颗种子的个别离群小节带偏，而 12 种子聚合完全正常。**群体性质不该由单颗种子决定。**
- **我第一次把四种手法全改到动机上，是过度实现。** 「让功能真的工作」不等于「让所有相关路径都走同一份数据」。隔离实验的价值在于：它把「要不要全改」这个模糊问题变成了两个可测数字。
- **`melody_unique` 从 ~32 降到 30.17 是可接受的代价**：主题真的会回来，48 小节里出现 15% 的重复是主题的定义，不是缺陷。相邻重复仍是 0，指纹护栏没被绕过。
