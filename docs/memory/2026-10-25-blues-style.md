# 2026-10-25 · 新增蓝调曲风（迭代轮次 58 · 音乐内容）

## 做了什么

前端跟弹三件套（轮次 55–57）闭环后转向音乐内容侧。第一个内容轮：**候选词汇表扩容——新增「蓝调 Blues」曲风预设**，这是轮次 20 以来第一次动 `STYLES`。

**领地**：`music.js`、`index.html`（两处静态 UI 清单）、`test/theory.test.mjs` + 文档。

1. **blues 预设**：`modes: ['mixolydian', 'minor']`（mixolydian 的 b7 音阶正是布鲁斯旋律的骨架，SCALES/PALETTE_QUALITY 早就有它，此前没有任何风格用它——这不是加新机器，是给既有零件找到了用途）；进行池全是属七骨架 `I7/IV7/V7` + `bVII` 色彩（大调侧）与 `i7/iv7/V7/bVI`（小调侧）；`swing: 0.55` 全场最高（shuffle 就是蓝调的身份）；`lh: shell/stride/walk/octave`。
2. **进行设计避开相邻同和弦**：12 小节蓝调原型的直译是 `I7 I7 IV7 I7`（同和弦连排），但 candidates.js 的**循环锁死断路器会把连续重复根音剔出候选**——照抄会和自己的护栏打架。改用 `V7–IV7–I7` 回环式走向，听感等价（转折位保留），护栏零冲突。这个取舍写进了代码注释。
3. **关键词路由修正**：`KEYWORD_HINTS` 此前把「蓝调/blues」错路由到爵士（jazz 正则里混着 blues 词）——拆成两条：爵士保留 爵士/jazz/摇摆/swing/酒吧，蓝调拿走 蓝调/blues/布鲁斯/shuffle → `mixolydian`。
4. **UI 两处静态清单**：实时页 chip 与工作室 select 各加「蓝调」（这两处不是从 STYLES 生成的，加风格必须两边都补——`dom-contract` 测试不查 option 对应，此处靠理论测试锁 STYLE_BY_ID 存在性）。

## 坑（一个）

- 关键词路由是**首个命中制**（`find()` 顺序 = 优先级）：测试输入 `'blues night'` 被**第 1 条**「雨|夜|night → 浪漫」劫走，蓝调根本没轮到。不是实现的错——顺序就是优先级，含「夜」的词归雨夜是既有设计。测试输入要避开歧义词（改用「布鲁斯 shuffle」），并把这条写进测试注释。

## 设计取舍

- **不加 12 小节曲式**：曲式（FORM_TEMPLATES）与和声骨架是两层；blues 的和声词汇 + shuffle + mixolydian 已给出蓝调身份，12 小节回环需要动曲式层（段落模板按 12 小节切分），那是另一个决策层改动、需要重新校准 gate 的独立轮。
- **bVII 入池**：mixolydian 的自然音级，功能归因 Tp——蓝调的「回到 bVII 再回家」由候选集合法表示，模型可以选它（模型只做选择，代码只做渲染的红线不破）。
