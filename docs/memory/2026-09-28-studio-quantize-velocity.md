# 2026-09-28 · 卷帘量化 + 力度轨（迭代轮次 15 · 前端）

> 计划：[../superpowers/plans/2026-09-28-studio-quantize-velocity.md](../superpowers/plans/2026-09-28-studio-quantize-velocity.md)
> 模式：impeccable **Operate**（用户在完成任务，扫读性 > 表达）

## 起因

两件从第 1 轮就挂着的事：卷帘**量化**与**力度编辑**。卷帘此前的编辑能力只有「增/移/缩/删/撤销」——**它完全无法修正时值与力度**，而生成的小节恰恰带着摇摆与人味。

## 证据

10 种子 3854 个音符：

| | 值 |
|---|---|
| 偏离 1/4 网格 | **54.3%** |
| 偏离 1/8 网格 | 25.8% |
| 偏离 1/16 网格 | 0.9% |
| 力度跨度 | 0.21 – 0.87（中位 0.37） |
| 时长跨度 | 0.06 – 6.08 拍 |

**过半音符不在 1/4 网格上**——量化是真实可用的编辑动作，不是锦上添花。

## 做了什么

1. **`quantizeNotes(piece, {grid, strength, hands})`**（纯函数）：吸附 onset 到 1/4·1/8·1/16。`strength` 支持**部分量化**（DAW 惯例：可以「收一半」而不是二选一）。**只动 onset**——时长与力度是另外两个独立维度，量化不该顺手改它们。返回被移动的音符数供 UI 反馈。
2. **力度轨**：卷帘下方一条 54px canvas，每个音符一根竖条（底部对齐、高度 ∝ 力度、颜色随手别、顶端加帽让「改了没有」一眼可见）。拖动竖条改力度，走**既有 `commit()`**——撤销栈、自动保存、`invalidateTension` 全部自动生效。

## 关键决策：把力度轨放进同一个 `.rollwrap`

力度轨与卷帘**共用 `ZOOM` 像素/拍**，且同在 `.rollwrap` 内。播放头是 `position:absolute; top:0; bottom:0`——**它天然覆盖两条轨，横向滚动也自动同步**。**零同步代码。**

这是第 6 轮「对齐是构造出来的，不是同步出来的」的延续：同一个手法第二次使用时成本更低，因为坐标系已经是共享的。

## 反思

- **连续两轮被测量否决之后，这一轮刻意选了高成功率的事**。不是回避难问题，而是先把交付节奏稳下来——**「确定有价值」和「可能有价值」都要做，但顺序有讲究**。
- **部分量化（`strength`）是这一轮里我最先想到、也最舍不得砍的设计**。二选一的量化器在音乐上很粗暴：生成的小节带摇摆人味是**特性**不是缺陷，用户常常只想「收一半」。砍掉它会让这个功能从「好用」降级为「能用」。
- **复用既有 `commit()` 让我没写一行撤销/保存代码**。力度编辑的 undo 不是我写的，是接上去的——**新能力搭在旧骨架上，比重写一遍便宜得多，也少一堆 bug。**
- **没做的**：力度轨只支持单音拖动，没有框选/批量、没有力度斜坡（ramp）、没有量化强度滑杆（后端已支持 `strength`，UI 未暴露）。这些是有意的克制——先让「能用且不破坏」，再谈「好用」。
