# 问答标记可见化（轮次 24 · 前端）· 2026-09-30

## 做了什么

轮次 23 的问答语义（`decision.phraseRole`）此前只在决策数据里。本轮让它可见（零新增 id）：

- **功能轨第三槽**：问句尾格子显示「问」、答句尾显示「答」（`PHRASE_ROLE_ZH`/`PHRASE_ROLE_FULL` 单一来源）。**文字 + 形状双通道**：「问」额外带虚线下划线——「悬而未决」的形状线索；「答」实字。**不占用功能颜色**（颜色归和声功能，是本项目的一维一通道纪律）。
- **决策日志**：问句/答句小节加「问句·半终止（悬而未决）/答句·全终止（收束回家）」文字标签。
- **图例三处同源**：`LEGEND_ITEMS` 新组「乐句语气」两条（覆盖面测试加「问句」「答句」关键词）、行内图例（index.html 的 `.fn-legend`）补 问/答、图例抽屉由 `renderLegend` 自动带上。**标记改了图例没改，比没图例更糟**——覆盖测试是守门人。
- CSS：`.fnseg .qa` 槽样式 + `qa-q` 虚线形状 + 图例 swatch（transparent + dotted 底边——「问」的图例块本身就是那条虚线的样子）。

测试 137→**138**。

## skill 规则落点（ui-ux-pro-max chart 域，第三次复用）

*"Mark anomalies with a distinct shape and text annotation as well as color. Do not rely on color alone."* —— 问句的「悬而未决」用**虚线形状 + 文字**表达；就算颜色通道全部失效，问/答仍然可读。

## 验证

- npm test **138/138**；`node --check` 全过；id 契约未新增
- 12 种子指标不变（纯展示层——phraseRole 数据轮次 23 已落地，本轮只读它）
- `fnSegClass` 冒烟：问句 → `fnseg fn-T qa-q`，答句+断路 → `fnseg fn-T qa-a lock`

## 明确不做

- **工作室卷帘的功能带不画问答标记**：12px 高的小节带塞第三个字符会糊掉；卷帘头部已有张力/功能/和弦/契合度四段信息。如实记录取舍，若日后有需求应做成 hover 读数而非常驻字。
- 旋律终止感的增强（如问句尾不锚主音）不做——开放感已由和声承载（轮次 23 验证过），双重强调会过。

## 反思

- **归因字段是前端轮的「半成品仓库」**：轮次 3（loopLocked/rejected）、轮次 12（develop）、本轮（phraseRole）都是内核轮先埋归因、前端轮兑现显示——决策归因的设计时就应该想好它的显示通道，否则归因只是给日志看的。
- 图例的「同源」测试第三次显灵：加标记 → 测试红 → 图例补上 → 绿。**人肉同步三处（轨、行内图例、抽屉）靠的不是一个细心的 agent，是一条会红的测试。**
