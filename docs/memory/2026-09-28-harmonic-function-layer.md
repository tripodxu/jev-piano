## 起因：第 1 轮留下的问题

第 1 轮接线循环锁死断路器后，`unique_chords` 仍停在 6-7。当时判定这是**曲风词汇上限**：
`chordCandidates` 的候选全集**严格等于进行池的并集**，romantic 小调 4 条 pool 共 {i, bVI, bIII, bVII, iv, V} → 6 个根音 → 天花板约 6-8，与调参无关。

所以这轮不是调参，是**换候选集的来源**。

## 做了什么

三层结构，代码、模型、算法各归其位：

```text
乐理层 music.js       调式音阶 → 全调内色板（带调式性质）
功能层 candidates.js T/S/D/Tp 四功能 + 功能转移矩阵 + 共同音/五度圈加权
模型层 composer.js   Jev 第 7 问「和声功能」；和弦仍在候选集内选
```

1. **和声功能分类**（`music.js`）：`HARMONIC_FUNCTIONS` + `functionOf(roman, mode)`，T 主 / S 下属 / D 属 / Tp 离调色彩。
2. **调式全色板**（`music.js`）：`modePalette(mode)` 由 `SCALES[mode]` 推导，外加 `PALETTE_QUALITY` 决定**性质**——大调出 `viiø`，小调出 `iiø`，dorian 出 `bVII`，这是标准的自然音级和弦表。
3. **声部进行打分**（`candidates.js`）：`commonTones()`（音级交集）+ `fifthsDist()`（五度圈环形距离），`smoothness = 共音数 − 0.25×五度距离`。这是经典的"五度圈进行生成"思路——权重从声部进行的物理代价推出来，而不是拍脑袋。
4. **功能转移矩阵**（`candidates.js`）：`T→{S,D}`、`S→{D,Tp}`、`D→{T}`、`Tp→{D,T}`，乐句尾抬 `D→T`。
5. **第 7 问「和声功能」**（`composer.js`）：Jev 先说下一小节要往哪个功能走，和弦仍在候选集内选。**不做硬过滤**——同一请求里无法先问功能再问和弦，硬过滤会让模型自己的合法作答被前置问题判死（设计文档 §3 已论证并否决）。
6. **功能族内回落**：和弦作答非法时，不回落到"全局最高权重"，而回落到**「模型声明的功能族」内权重最高**的候选。模型已经用一句话告诉了我们要往哪走——这比原来的兜底聪明。
7. **顺手修两个真 bug**（见下）。

## 顺手修掉的两个真 bug

| bug | 症状 | 根因 |
|---|---|---|
| 旋律护栏"逃出去又被改回来" | 乐句尾（第 8/16/24 小节）出现相邻旋律字面重复 | `mutateMelody` 判定的是**未锚定**形态，判定完第 611 行又把 `snapLastToChord` 打回去；存进 `lastSigs` 的却是**已锚定**形态——比对的是两种不同形态。修法：把 `post` 传进护栏，在**最终形态**上判定 |
| 旋律护栏兜底返回撞车原样 | 所有变形都撞车时 `return rh`，直接返回了一个已知撞车的旋律 | README 宣称的"绝不逐字重复"是假的。修法：加 4 个**可证有效**的节奏压缩变形（签名含 onset，4 个互异压缩比里必有 ≥2 个与已存的 2 个指纹不同）+ 音高绝对扫掠 + 删末音 |

另外发现**左手根本没有指纹护栏**——`renderLH` 靠随机变体（空拍/旋转/换序）避重但无硬保证。色板词汇变宽后实测 1/12 种子出现相邻左手复读。已补上同构的左手护栏（撞车就重渲染换一个变体，rng 继续推进所以同 seed 仍可复现）。

## 反思

- **只扩根音是伪解。** 第一版色板只输出根音的罗马数字，结果 C 小调色板比进行池只多 1 个（D），而 `poolTop.slice(0,6)` 的名额被池和弦占满——扩充根本进不了前 8 候选，等于死代码。真正的天花板在**符号**（i/iiø/bIII/iv/V/bVI/bVII 及其七和弦/悬挂），不在根音。**教训：动手前先确认"瓶颈单位"是什么**；根音数天然封顶于调式音级数，符号数才不会。
- **硬不变量 > 软指标。** `W_SMOOTH` 调到 0.35 能把音程熵抬到 2.57（过门），但旋律相邻重复在 3/12 种子上失败。毫不犹豫回退到 0.5 并把原因写进代码注释。软指标的 0.04 提升换硬不变量破损，不划算。
- **我在自己的测量脚本里犯了和项目同类的错。** A/B 脚本把 `melody_adjacent_repeat + lh_adjacent_repeat` 相加成一个 `adj`，导致我一度以为是旋律护栏失效、连续改了两次代码。分开看才发现旋律硬门一直是 0，问题在左手。**指标合并会掩盖失效部位**——这正是本项目候选集"把语义混在一起"的同一类错误。差点因为指标口径错误而改错代码。
- **音程熵差 0.06 我选择不掩饰。** 12 种子均值的标准误约 0.09，−0.06 在噪声内，既不算改善也不算退化；但门槛是我自己定的，没过就是没过，如实记录。共同音加权让声部更平滑，跳进占比虽然 +1.5 个百分点补偿了一部分，熵仍略降——这是真实的取舍，不是免费的午餐。
- **色板"质"是全项目词汇的总开关。** `PALETTE_QUALITY` 一改，8 种曲风全部调式的候选词汇都变。它现在是高危区，已写进 AGENTS.md 代码地图的"修改高危区"列。
- 计费：本轮真实渠道 2 次 32 小节编曲，约 $0.004。
