# 2026-09-28 · 段落/曲式规划（迭代轮次 8 · 创意）

> 计划：[../superpowers/plans/2026-09-28-form-sections.md](../superpowers/plans/2026-09-28-form-sections.md)

## 创意核心

> **给 plan 装上段落结构**，让 README 远期路线图第 3 条（大模型做系统二的曲式规划、Jev 做系统一的小节级选择）真正落地。

`plan.sections` = `[{id, arc, level, swing, bars, start}]`，经典四段式 **A 陈述 → B 对比（全曲峰值）→ A' 再现 → Coda 收束**。LLM 可以给出自己的段落（提示词里是可选项），不合法就回退到按弧线派生的模板。

段落不是装饰：`intensityTarget` 改为**段落感知**——每段用自己的 `arc` 与 `level`，段内再走局部弧线。段落长度恒为乐句长度的整数倍，**段落边界与乐句边界天然对齐**。

## 证据（动手前先量）

`scripts/tmp-form.mjs` 数张力曲线的显著峰（12 种子）：**平均 2.42 峰，分布 `4 3 2 2 2 1 2 3 0 4 3 3`**。形状（seed 2020）：

```
▇▇▇██▇▇███▇▇▇▆▆▆▆▇▇███▆▇▇▇▆▆▇▆▆▆
```

那些"峰"是织体造成的噪声尖刺。一条 `fall` 弧线不该在第 4、8、15、23 小节各冒一个峰——**张力被高频噪声淹没，形式不可见。**

## 反思

- **我第一版的测量仪器是错的。** 我用「张力峰数」衡量形式是否建立，测出 2.42→2.25（变差），一度以为方案失败。真相是：那个 prompt（`雨夜的城市`）**永远映射到 `fall` 曲式**，而**下降曲式按定义就只有开场一个峰**。我在用一个对 `fall` 天然不适用的指标去否定 `fall`。换成「实现张力 vs 目标的相��性」后，结论完全反过来。**指标选错时，负面结果是噪声而不是证据。**
- **既有的 `rise` 相关性测试抓到了一个真问题。** 我把 `rise` 的 Coda 设成 0.9，比开场的 A（1.2）还低——「欢快庆典」的曲子收得比开场更安静，反直觉。**Coda 是收束，不是归零**，它的 level 应该相对该曲式而非绝对。改成 1.9 后既有测试恢复通过。**一个 2024 年就写下的测试，抓到了 2026 年才引入的 bug。**
- **「B 段是全曲峰值」是我的想当然。** 测试报 `rise 的峰值段不是 B` 时我才想清楚：`rise` 的峰值在再现段（2.1 > B 的 1.9），`fall` 的峰值在开场。**峰值位置随曲式而变，这是对的音乐。** 于是把断言改成真正普遍的规律：Coda 恒低于该曲式峰值、恒以衰减/静止收尾、必有 B 对比段。
- **顺手修掉一个我差点漏掉的不一致**：`tension.js` 的 `targetSeries` 还在用**全局弧线**画「计划弧线」幽灵线，而音乐已经跟段落走了——实时界面会显示一条对不上的参照线。把它移到 `candidates.js` 并改名为 `planTargetSeries`：**它由 `intensityTarget` 派生、描述的是「计划」而非「已生成的音乐」，放在分析层会造成反向耦合。**
- **新曲线相关的测试容易写错**：我在单引号测试名里写了 `A\' ... A''`，第二个 `'` 把字符串提前闭合，报的却是 `SyntaxError: missing ) after argument list` —— 与出错位置毫无关联。**语法错误的报错信息可能来自完全无关的地方。**
