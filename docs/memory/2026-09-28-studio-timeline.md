# 2026-09-28 · 工作室卷帘时间轴（迭代轮次 6 · 前端）

> skill：`taste-skill`（**其 §13 明确声明不适用于密集产品 UI**，见反思）+ `impeccable` Operate 模式

## 起因

前两轮给实时即兴加了两块可视化（和声功能轨、张力对照带），工作室却零可视化。而工作室恰恰是**整曲已知**的地方——那里才是看全貌的正确场合，「实时」只是为了等它生成出来而已。

## 核心设计决策：画进卷帘自己的画布

最直觉的做法是给工作室加两个独立控件（一条功能带 + 一条张力曲线，各一个 canvas）。否决了——**那会引入两套横轴，需要写滚动同步、缩放同步、播放头同步**。

实际做法：把两者**画进钢琴卷帘自己的画布头部**。

```text
卷帘头部（HEADER 16 → 54）
  ┌──────────────────────────────┐
  │ ▁▂▅▇▅▂▁  ← 张力面积（24px）  │
  │ ▓▓▒▒██▓▓  ← 功能带（12px）    │  与下方音符区共用 ZOOM=24 px/拍
  │ Cm Fm G Ab …  ← 和弦名（18px）│
  ├──────────────────────────────┤
  │  钢琴卷帘音符区               │
```

**对齐是构造出来的，不是同步出来的。** `x = startBeat * ZOOM` 这个式子在画布里只写了一次，三段视图永远同步——改 `ZOOM` 三者自动跟随。零同步代码、零状态、零 bug 面。

## 做了什么

- `music.js`：新增 `functionOfPc(rootPc, mode)`（`functionOf` 委托给它）。**为什么需要**：旧项目 JSON 里没有罗马数字可解析，只有 `rootPc`。
- `studio.js`：
  - `barChords` 在生成时多存 `fn`（决策归因）与 `intensity`——两者原本就没被保存，而工作室里一个都没用上。
  - 新增两个可单测的纯函数 `barFunction`（归因优先、根音回推兜底）与 `pieceTension`（把 piece 还原成可交给 `barTension` 的小节）。
  - `drawTimeline` 画张力面积 + 功能带；`HEADER` 16→54。
  - 张力缓存 `tensionCache` + `invalidateTension()`，在**每一处**音符改动后调用（`commit` / `doUndo` / `doRedo` / `setPiece` / Jev 修订 / 重新生成）。
- 测试 83 → **86**。

## 反思

- **`taste-skill` 自己说了不适用。** 它的 §13 写得很清楚："This skill is NOT for: dashboards / dense product UI"。钢琴卷帘正是密集产品 UI。所以我没有硬套它的规则——它那条"premium-consumer 配色禁令"（禁 beige+brass+oxblood+espresso）看着正好打中本项目，但我判定**不适用**：那条针对的是消费品牌（厨具/香薰/手工皮具），而这是乐器；而且 impeccable 的 craft-floor 明确「已确立的视觉世界优先于本清单」。**工具声明自己不适用时，照用反而是错的。**
- **对齐问题的正确解法是消除问题，不是管理问题。** 我最初想的是"加两个控件然后同步它们"，那是在给不存在的问题写胶水。改成共用一个坐标系后，同步问题**根本不再存在**。**当你发现自己在写同步代码时，先问能不能共享状态。**
- **缓存作废点是这类改动最容易漏的地方。** 张力依赖音符（密度/音域分量），所以任何增删改音符的路径都必须 `invalidateTension()`。我逐个找了 6 处（`commit`/`doUndo`/`doRedo`/`setPiece`/Jev 修订/重新生成）。漏一处就是「曲线不跟着编辑更新」这种极难复现的幽灵 bug。已写进 AGENTS.md 高危区。
- **旧格式兼容要显式测，不能靠想。** `pieceTension` 面对的是**上一轮之前生成、存在 localStorage 里的旧 JSON**——没有 `fn`、没有 `intensity`。回退路径（`functionOfPc` 推导功能、`intensity ?? 1.5` 中性值）写完必须配一条"旧格式仍产出合法张力"的测试，否则这类 bug 只会在真实用户的浏览器里出现。
