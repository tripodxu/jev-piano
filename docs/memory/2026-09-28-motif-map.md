## Delight thesis

> **「你的主题在曲子里回来了」**

`impeccable/delight` 的核心判据是「**这个瞬间必须只有这个产品做得出**」。别的 AI 音乐生成器给你音频，不给你可溯源的结构；而第 11 轮才让「主题真的会回来」这件事成立（音程差 3.76 → 0.87）。**新造的能力如果没有被看见，等于没造。**

## 做了什么

1. **动机卡（MotifCard）**：第 2 小节动机诞生时，把它的旋律轮廓画成一条曲线——曲子的「形状」，并累计「回来 N 次」。首次再现后约 900ms 有一次静默强调，之后回到常态。
2. **功能轨上的发展手法通道**：每段加第二行标记（承/模/倒/装）。**颜色归和声功能，形态归发展手法**——两个维度各用一套通道，互不干扰。承袭额外给**顶部括线 + 亮边**的形状。

## 关于「不依赖颜色」

这是第 9 轮 `ui-ux-pro-max` 查到的硬规则（*"Do not rely on color alone"*）在本轮的延续：功能轨已经用颜色编码了和声功能，如果发展手法也只用颜色，灰度下整条轨会退化。所以：

- 功能 = 颜色（黄铜/冷青/猩红/旧金）
- 手法 = **文字**（承/模/倒/装）+ 承袭额外给**形状**（括线）
- 段落 = 虚线竖线 + 段落名

三套通道互不重叠，每套都独立可读。

## 反思

- **`motifShape` 的归一化让「同一形状」可判定**：整体移调不改变轮廓（`[72,74,76,72]` 与 `[60,62,64,60]` 形状完全一致）。这不只是画图需要——它让「主题回来了」在视觉上成为一个可辨认的事实，而不是逐音高比对。
- **全同音的边界情况暴露了一个我没想的语义**：我原本用 `span || 1` 兜底除零，结果平线被贴在**顶边**。但「一条平线」放中线才符合直觉。这是测试替我想到的——**测试的价值往往在于覆盖你没想过的形状，而不是验证你想过的那一个。**
- **`DEV_ZH` 重复声明**：我加导出时没注意到文件里已有一个同名私有常量，模块直接 SyntaxError。`node --check` 抓到了——**它抓的是语法，这类问题不会在运行时静默。**
- **delight 的判据帮我拒绝了廉价的做法**：我完全可以给每次承袭都加一个闪烁特效。但「不要为普通点击制造庆祝」+「重复一百次还讨喜是它的判据」让我把强调**限制成一次性、900ms、不加依赖**。**克制的彩蛋比华丽的动画更接近「被设计过」。**
