# 时间维可见化（轮次 21 · 前端）· 2026-09-30

## 做了什么

轮次 20 给了计划一根时间轴，但界面上任何地方都看不到它。本轮用**三个通道**把它显形（零新增 id、零新增 canvas）：

1. **计划卡**：速度行 `速度 80 BPM · 尾段渐慢至 64`——新纯函数 `planTempoLine(plan)`（脏输入返回空串，调用方回退旧格式）。数字来自 `tempoMultAt(末小节)`，写的是计划的真实幅度，不是装饰性"rit."字样。
2. **实时读数**（nowBar）：`第 25 小节 A1 · 强度 2.3 · 速度 86`——Coda 渐慢时数字**当着用户的面掉下去**，rit. 从「计划里的一句话」变成「正在发生的事」。
3. **张力带 hover**：crosshair + 画布内文字读数（`第 N 小节 / 张力 · 计划 / 和弦 · 速度`）。`TensionGraph.pushMeta({chord, speed})` 与 `push` 同调喂入；`hoverBarAt(px, W, n)` 纯函数命中小节。

测试 128→**132**。

## skill 规则的落点（ui-ux-pro-max · chart 域）

- *"Relying on hover only"* 是反模式 → hover 只是增强：无 hover 的读法（tensionStat 文本行、aria-label）始终存在。这恰好是本项目「三套独立通道」原则的第三次自然复用。
- 触屏拖动等同 hover（pointermove），移动端不是死通道。
- **克制**：不引入 DOM tooltip 组件——读数画进 canvas，指针离开即消失。上一轮 onboard 的「别为普通交互制造仪式」在这里同样适用：hover 读数是查询行为，不该留下任何痕迹。

## 反思

- **「新能力不可见 = 没交付」第二次应验**：轮次 12 的动机卡、本轮的时间维，都是内核先落地、界面补可见性——而且都是在前端轮里用最少的通道（文字优先于新图层）补齐。新维度的默认展示成本应该接近零，否则会在「做出来」与「被看到」之间断掉。
- **hover 的克制判据**：hover 读数该不该存在？问「用户在什么时刻需要它」——看曲线时想知道「这个低点是小节几、什么和弦」。是查询不是通知，所以答案画在指针旁边、随指针消失，而不是常驻面板。
