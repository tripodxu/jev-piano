# 2026-09-28 · 循环锁死断路器接线（迭代轮次 1 · 优化）

> 计划：[docs/superpowers/plans/2026-09-28-loop-lock-breaker.md](../../superpowers/plans/2026-09-28-loop-lock-breaker.md)

## 起因

MEMORY 里挂着一个 [阻塞] 条目：「真实 Jev 重复度基线：和弦多样性未达标（unique_chords=6 < 8）」。
全量阅读代码时发现根因不在参数，而在**一个从未接线的机制**：

- `composer.js:134` 的 `chordCandidates(..., recentRoots, fatigue)` 第 7 个参数 `recentRoots` 是**死参数**——JSDoc 明写「循环锁死时循环成员直接从候选中剔除」，函数体却从未引用它。
- `detectLoop` 的 `members` 字段全仓**零消费者**；它的返回值只被拿去填 `state.harmony.loop_locked` 当提示给模型看。
- 调用方（`composer.js:589-591`）和既有测试（`composer.test.mjs:162`）**早就在传这个参数**——接口留好了，实现没写。

也就是说：反重复大修（a085f4f）宣称的两条和声断路器里，「循环锁死」这条**从来没运行过**。真实 Jev 的 `Cm-Fm-G` 字面三和弦循环之所以拦不住，是因为根音疲劳（阈值 2.0、衰减 0.93）在 6 小节窗口内根本攒不到阈值。

## 做了什么

1. **接线循环锁死断路器**（`candidates.js` 的 `chordCandidates`）
   - 顶部算一次 `detectLoop(recentRoots)`，锁死时把循环成员（窗口内出现 ≥2 次的根音）剔出候选；替换和弦（副属/借用/悬挂）走同一过滤，不能偷渡。
   - 两条断路器的**取舍顺序**：三段构建 `build(true,true) → build(false,true) → build(false,false)`。优先放掉疲劳、保留锁死——疲劳是自衰减的软约束（等得起），锁死是当小节正在发生的硬事实（等不得）。

2. **顺手修掉一个既有潜伏 bug**：兜底判据原本写成 `if (!out.length)`（非空），但真正的不变量是「候选够用 ≥3」。断路器很凶时主池被剔光、只剩 1 个替换和弦幸存，`out.length===1` 不触发兜底 → 该风格**只剩 1 个候选**。实测 waltz 全池疲劳时确实只返回 `II7` 一个。改为 `out.length < 3`。

3. **抽出 `public/js/candidates.js`**（171 行）：把候选集构造整体搬出 `composer.js`（769 → **616** 行，ADR-0004 的 800 行上限不再逼近）。搬迁是逐字复制，只改 `chordCandidates` 内部。分工变成：候选集回答"哪些选择合法"，渲染内核回答"怎么变成音符"。

4. **决策归因字段**（ADR-0003 后果条款要求"元信息应能表达发生了剔除"）：`bar.decision.loopLocked` / `bar.decision.rejected`。留给下一轮前端轮做可视化。

5. 测试 47 → **55**（新 `test/candidates.test.mjs` 9 项；composer 测试把两条候选集测试迁过去并补归因测试）。

## 反思（本轮最大收获）

- **`unique_chords` 停在 6-7 不是断路器失效，是曲风词汇上限**。romantic 小调的进行池只有 i/bVI/bIII/bVII/iv/V 六个根音，模型能选的合法和弦本来就那么几个。指标盯错了对象——真正该盯的是"是否连续 N 小节停在同一组和弦"，而那恰恰是本轮改善最大的（左手唯一 23→30）。**下一轮若要继续提 `unique_chords`，该动的是 `STYLES` 的进行池词汇量，不是断路器参数。**
- **单种子指标不可信**。最初拿 4 个种子跑出"8.5→8.25，看着像退化"，扩到 12 个种子才看清是噪声。已把这条写进 AGENTS.md 的命令注释。
- **真实渠道非确定性**，同 seed 两次跑结果不同；单次 A/B 只能作为"是否还出现同样的字面循环"这种**定性**证据，不能当定量指标。
- **死参数是最危险的 bug**：签名、JSDoc、调用方、测试全都在，只有实现不在——所有静态检查和 review 都会放过它。发现这类"接口齐备但行为缺失"的缝隙，比调参更值得优先做。
