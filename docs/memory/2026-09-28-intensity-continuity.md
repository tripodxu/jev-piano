# 2026-09-28 · 强度连续化（迭代轮次 7 · 优化）

> 计划：[../superpowers/plans/2026-09-28-intensity-continuity.md](../superpowers/plans/2026-09-28-intensity-continuity.md)

## 起因

轮次 5 做张力曲线时顺手看见的东西：fixture 的 `intensity` 序列是 `3 2 3 2 0 2 3 3 3 2 2 0 1 0 0 0 2 0 3 2…`——**是噪声，不是弧线**。

动手前先量（`scripts/tmp-intensity.mjs`，跑完即删），12 种子 × 32 小节 = 372 次相邻跳变：

| 指标 | 值 |
|---|---|
| 平均跳变 | **1.032 档**（4 档量表里相邻小节跳整整一级） |
| 跳 ≥2 档 | **26.9%**（100/372） |
| 跳 ≥3 档 | 6.2%（23/372） |
| 分布 | 0档×111 · 1档×161 · 2档×77 · 3档×23 |

对照同种子的计划弧：`2.4 2.3 2.3 2.2 2.2 2.1 2.1 1.5 1.9…`——一条平滑的下行线。

**根因**：计划弧是连续曲线，而 Jev 的 `score` 问按 API 契约**只能返回整数档**，代码把这个整数直接当绝对值渲染。音乐意图在量化那一处被摧毁了。后果：力度 0.35↔0.85（**2.4 倍落差**），且左手织体的三个分支阈值（`intensity<1` / `>=1.5` / `>=2`）在整数档翻转时同时改变音色。

**这不是 fixture 的问题**——真实 Jev 同样受同一份 API 契约约束，所以生产环境一直在播跳档的动态。

## 做了什么

两步，都在**渲染层**，都不夺走模型的决定权（ADR-0001）：

1. **dev = 0.5（偏移权重）**：把整数回答重新解释为「**相对计划弧线的偏移**」而不是「绝对多响」。模型同意计划就得到计划，偏离则保留一半偏离。
2. **slew = 1.0（速率限制）**：限制**变化率**而非目标值——这就是音频侧压缩器的 attack/release 与 MIDI CC 平滑的同一思路。模型仍决定去哪里，只是不能一小节跳三档。

参数不是拍脑袋定的：`scripts/tmp-slew.mjs` 用录下来的真实序列**重放模拟**了 7 组组合：

| 方案 | 平均跳变 | 跳≥2 | 最大 |
|---|---|---|---|
| 现状 | 1.032 | 26.9% | 3.00 |
| 仅 dev=0.5 | 0.556 | 0% | 1.78 |
| 仅 slew=1.5 | 0.820 | 0% | 1.50 |
| **dev=0.5 + slew=1.0（采纳）** | **0.495** | **0%** | **1.00** |
| dev=0.35 + slew=1.5 | 0.414 | 0% | 1.41 |

选 dev=0.5 而非 0.35：后者指标更漂亮，但**会过度削弱模型**——0.414 与 0.495 的听感差别远小于「模型还剩多少发言权」的差别。平滑不该以架空模型为代价。

## 反思

- **一个可视化的副产品，抓到了一直存在的听感 bug。** 轮次 5 的张力曲线本身是展示层，指标逐位不变；但正是它把 `3 2 3 2 0 2` 这串噪声**摆到了眼前**。**让内部状态可见，往往比直接审计它更有效**——审计要你知道该看什么，可视化不用。
- **`lh` 降了 1.16，是我预判内的代价不是意外。** 强度平滑 → 更多相邻小节落进同一个左手分支 → 左手小节之间更相似。但**左手指纹护栏（轮次 2 加的）把 `lh_adjacent_repeat` 守在 0**——两层机制在这里接上了力：上面那层让音乐更顺，下面那层保证不因此重复。**如果当初没建左手护栏，这一轮就会撞硬门。**
- **浮点让「最大跳变 = 1.0」变成 `1.0000000000000002`。** 写测试时用了 `<= 1.0 + 1e-9` 的容差而不是 `=== 1.0`。速率限制的输出必然带浮点残差，**测试断言整数等值会是长期噪声源**。
- **先重放模拟再改代码，成本远低于改完再调参。** 7 组参数一次算完，改代码时参数已经是选定的而不是试出来的；`npm test` 只用跑一遍就知道过不过。

## 教训沉淀

- **受限的 API 契约会摧毁连续量。** 整数档不是模型的错，是接口的形状；渲染层该做的是**重新解释**（整数→偏移）而不是**照单全收**（整数→绝对值）。
- **平滑有两个旋钮，第二个常被忽略**：往目标混多少（dev）、允许多快到（slew）。只调 dev 会被极端跳变打穿（最大仍 1.78），只调 slew 则会让模型偏离计划太多。
