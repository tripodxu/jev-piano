# 速度弧线（轮次 20 · 创意）· 2026-09-30

## 做了什么

整曲此前从头到尾一个速度——曲式有两根轴（响度 × 时间），张力弧线已段落化（轮次 8），时间维度却是死的。本轮给计划的**时间形状**补上语义：

- `candidates.js` 新纯函数 **`tempoMultAt(plan, bar)`**（311→343 行）：每小节一个速度乘数，小节内恒定。最后一段线性 rit.（1.0→**0.8**，用「最后一段」而非 `id==='Coda'` 判断——LLM 的 sections 允许任意 id）；非尾段的 `arch`/`rise` 段轻微推进（**1.04**）；无 sections 的旧 JSON 走兼容路径（最后 1/4 缓降到 0.85）。与 `intensityTarget` 同层同约定：脏输入降级、绝不抛错。
- `player.js` `_enqueueBar` 从「恒定 secPerBeat × 绝对拍」改为**顺序游标累计**（`_cursorBeat`/`_cursorSec`）：每小节用自己的乘数，乱序入队回退线性映射（防御路径，正常管线不会触发）。暂停/恢复语义不变——映射只依赖 `_t0` 与每小节时长表，不依赖真实时间流逝。
- `midi.js` `exportMidi` 接受 `tempoMults`：track0 按小节写 SMF `set_tempo`，plateau 不重复写；**不带参数时字节与旧版逐位一致**（有测试锁住）。
- 两个界面的 MIDI 导出都传入乘数序列——导出的 MIDI 保留「尾段渐慢」的演奏意图。

测试 122→**128**。

## 设计取舍（有意不做）

- **工作室回放保持恒速**：DAW 惯例是编辑视图恒速预览，工作室的 BPM 输入框就是速度事实源；但它的 MIDI 导出仍带曲线（编曲的完整意图）。
- **演奏指示不接入速度**：速度是系统二（计划）的领地，导演指示只影响强度与织体——混入会让「计划 vs 临场」边界变糊。
- **bar 内不做连续插值**：相邻小节差 ≤4% 时 bar 内变化不可闻，而连续插值要求 beat→sec 逐段积分，复杂度全在测试上。粒度选在感知阈值之上、复杂度爆炸之下。

## 坑（两次都是我的测试错，不是实现错）

1. **观察不到最后一小节的时长**：只入队到 bar 16，`marks[16]-marks[15]` 是 bar **15**（A 段）的时长——小节起点的差分给出的是**前一小节**的时长。要多入队一小节才能观察到 B 段变短。
2. **SMF meta 事件总长是 3 + ln 不是 2 + ln**：测试解码器少跳一字节导致后续解析全部错位，只找到 1 个 tempo 事件。二进制格式解析器的偏移 bug 表现为「找不到后面的东西」，第一反应该是检查解析器自己。

## 反思

- **「最后一根轴」的检查法**：轮次 8 给曲式加了响度轴后，没有人问「时间轴呢」——19 轮里每轮都在加**内容**（和弦/动机/段落），速度这种**元层**参数一直躺在默认值上。审计一个系统的完备性时，列出它所有连续参数（响度/速度/音区/密度），逐个问「计划层有没有管它」。
- 游标累计 vs 绝对映射：绝对映射（beat×spb）只在恒速下成立；一旦引入变速，「时间」就必须是**累计量**而非**函数**。这个选择在音频调度（A Tale of Two Clocks）和动画曲线里反复出现——能累计的量不要用公式反推。
