# 2026-09-28 · 非和声音分析（迭代轮次 17 · 创意）

> 计划：[../superpowers/plans/2026-09-28-non-chord-tones.md](../superpowers/plans/2026-09-28-non-chord-tones.md)

## 想法

延续「让内部状态可见」这条线：第 5 轮张力、第 2 轮功能、第 8/9 轮段落、第 11/12 轮动机。这一轮补上**旋律与和声的关系**——每个旋律音是和弦音还是非和声音，以及是**哪一种**非和声音。

分类判据取自 **Kostka-Payne《Tonal Harmony》** 的标准做法：不是「在不在和弦里」的二分，而是按音的**进出方式**区分——经过音（同向级进）、邻音（折返级进）、倚音（跳进后级进下行解决）。三种非和声音在听感上含义完全不同：经过音是流动，邻音是修饰，倚音是张力。

## 证据：音乐是调性健康的

12 种子 384 小节 / 1892 个旋律音：

| 类别 | 占比 |
|---|---|
| 和弦音 | **62.4%** |
| 经过音 / 邻音 / 倚音 | 6.0% / 7.0% / 3.1% |
| 其它非和弦音 | 21.6% |
| **非和声音合计** | **37.6%** |
| 不在调内音阶上 | 9.6%（半减/副属等变化音，正常） |

**非和声音 37.6% 落在古典语汇的 20–40% 区间**。所以这是「解释性」的分析而不是警报——它给用户一个此前没有的读数：**为什么这首曲子听起来是调性的**。

## 做了什么

- **新建 `public/js/nct.js`（53 行，分析层）**：`classifyNote` / `barHarmonyFit` / `harmonySummary` / `NCT_ZH`。与 `tension.js` 平级、同样无决策耦合——`nct.js` 只 import `music.js` 的 `chordPcs`，不碰 `candidates.js`。
- **工作室卷帘**：头部加第四段**契合度带**（每小节一根竖条，高度 = 和弦音占比，越高越「在调上」）；旋律里的非和弦音加**亮边**。
- **实时界面**：张力读数行补「和弦音 62%」。

**一维一通道**：手别 = 填色，非和音 = 亮边，左手恒为纯色不受影响。契合度带与卷帘共用 `ZOOM`，横轴天然对齐——第 6 轮起第四次复用这个手法，成本几乎为零。

## 反思

- **选纯分析层是对第 14 轮失败的直接回应**。那一轮证明了「渲染层无法用后验信息修正模型的选择」，所以这轮挑了一个**结构上不可能影响音乐**的方向——把新能力放在只读的分析层，指标退化的风险从结构上归零。**失败过的尝试会缩小下一次的搜索空间。**
- **「一维一通道」这个原则第三次奏效**（功能=颜色 / 手法=文字+形状 / 段落=虚线+名字 / 手别=填色 / 非和音=亮边）。每一维都有独立的非颜色读法，所以任何一维失效都不会让其它维度一起失读。
- **分类判据里最容易错的是首尾音**：把「4→5」判成经过音是错的，那只是半个经过音。测试专门锁了这条——**判据的边界比判据本身更容易出错**。
