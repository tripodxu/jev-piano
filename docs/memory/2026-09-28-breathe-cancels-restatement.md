## 诊断找到的缺陷

12 种子 384 小节的广谱诊断：

| 指标 | 值 |
|---|---|
| 发展手法分布 | repeat 17.2% · sequence 24.5% · inversion 14.3% · ornament 23.4% · new 20.6% |
| 呼吸小节 | 15.9% |
| **承袭中被呼吸取消** | **16/66 = 24.2%** |
| 音符落在 1/16 网格 | 99.1% |
| 旋律跳进 | ≤小二度 71.8% · ≤四度 19.2% · ≤六度 6.0% · >六度 2.9% |

机制：`motifReady` 与 `usePrev` 都要求 `!breathe`，所以 `develop === 'repeat' && breathe === true` 时走 `fresh()`。

**两个 bug 叠在一起**：
1. **音乐**：四分之一的「重述」什么��重述
2. **诚实性**：`decision.develop` 仍记 `repeat`，决策日志显示「承袭」、功能轨给它括线与「承」、动机卡给它**计数一次「回来」**——**归因在撒谎**，而这个项目的立身之本就是「每个音符可溯源」

## 做了什么

1. **呼吸不再取消承袭，而是让动机整体延后**。`buildFromMotif` 接 `breathe`，把全部 onset 后移「动机自身的最小音程间距」（从它自己的节奏里取，默认半拍）。比「丢掉第一个音」好——丢首音会破坏动机身份；整体后移则**两个模型决策都被兑现**：既重述了动机，又留了呼吸空档。作曲里「主题延迟进入」是真实手法。
2. **兜底路径修正归因**：若因任何原因最终走了 `fresh()`，`decision.develop` 与 `developHistory` 一起改为 `'new'`。**决策日志说真话是硬要求**，不靠调用方自觉。

## 顺带修掉一个第 11 轮的 bug

修完第一步后音程差只从 5.67 降到 4.25。打点一看：**前几个音程完全对上，只有最后一个偏**。根因在 `buildFromMotif`：

```js
if (onsets[k] % 4 === 0 || k === midis.length - 1) midi = nearest(midi, pool);
```

**末音无条件吸附到和弦音**——而第 1 轮的设计是 `snapLastToChord` **只在乐句尾**调用。我在第 11 轮把它改成了每小节都吸附，比原始设计更严；此前被「不延后」掩盖着，一旦延后就拽掉 7 个半音。已改为 `isPhraseEnd && k === last`。

**这是我自己在第 11 轮埋的、被后续改动揭出来的雷。**

## 两条判据修正（我的测试错了两次）

1. **轮廓比对原先含末音**。但末音在**乐句尾**会被解析到和弦音——那是第 1 轮的终止式设计，不是轮廓偏差。改为比对前 N−1 段，末音的契约交给既有的「乐句尾末音落在当前和弦内」测试守。
2. **段落首那个测试只用了 6 颗种子（24 样本）**，σ≈10%，把 21% 与 33% 判成一升一降**纯属噪声**。升到 12 颗（48 样本）。同时把 `1.8×` 的门槛降到 `1.3×`——那个数字是第 10 轮按当时 2.9× 定的，而实测比值随 rng 游走在 **1.55~2.06** 摆动（本轮改动让「呼吸」不再走 `renderMelody`，`buildFromMotif` 的 rng 消耗次数不同，**整条随机游走因此改变**）。要守的是「段落首明显偏向重述」这件事，不是某一个具体数字。

## 反思

- **这一轮最有价值的产出不是修复，是「归因必须说真话」这条被两轮 UI 强化之后浮现的检查。** 第 3、9、12 轮把归因字段（功能轨/段落标注/动机卡）做得越来越显眼，而承袭在 24% 的情况下其实没发生——**UI 越漂亮，说谎的代价越大**。
- **「两个模型决策同时成立时该怎么办」是一个被反复忽视的设计问题**。`repeat` 与 `breathe` 都是模型的合法选择，代码却让后者静默取消前者。正确做法是**让两者都成立**（延后），而不是**挑一个赢**。
- **我自己的 bug 会在几轮之后才暴露**。第 11 轮的「末音每小节都吸附」当时看不出问题，因为那时还没有「呼吸延后」这条路径。**改动会解锁旧 bug 的可见性**——所以每次改动都要重跑全套指标，不能只看新增的那条。
