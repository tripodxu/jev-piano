# 2026-09-28 · 张力对照带（迭代轮次 5 · 创意）

> 设计：[../superpowers/specs/2026-09-28-tension-band-design.md](../superpowers/specs/2026-09-28-tension-band-design.md)

## 创意核心

> 把「整首曲子演成什么样」画出来，并且和「原本打算演成什么样」叠在一起看。

项目从第一轮起就在讲「每个音符可溯源到一条决策」，但那一直是**单个小节**级别的。本轮把可溯源推到**整曲级别**：一条随演奏生长的张力曲线，外加计划弧线作为幽灵虚线。别的 AI 音乐生成器给你音频；这里给你**和声轨迹**。

## 原型先行（第 4 轮的教训：先量再改）

动手前写了 `scripts/tmp-tension.mjs` 验证算法站得住，三条证据：

1. **形状张力排序符合乐理直觉**：`maj3 .12 < sus4 .20 < m .24 < 7 .28 < maj7 .44 < dim .84 < m7b5 1.00`
2. **不是强度的换皮**：张力与 `intensity` 的相关只有 **0.41 / 0.46**。若接近 0.95，这个功能就只是把旧数字换个画法
3. **峰值落在正确的和弦上**：两个种子的全部峰值（0.69/0.71/0.77/0.78/0.79）**都在 `Dm7b5`（小调 iiØ）**——半减和弦是自然小调里最不协和的，算法自己找到了它

## 做了什么

- **新建 `public/js/tension.js`（97 行，分析层）**：`shapeTension`（音程不协和度，Plomp-Levelt 简化版）、`barTension`（五分量加权：和声 .34 / 功能 .24 / 音域 .16 / 密度 .12 / 动态 .14）、`targetSeries`（计划弧线）、`smooth`、`tensionStats`。
  **为什么不塞进 `music.js`**：那是乐理内核（音阶/和弦/声位）；张力是**对已生成音乐的分析**，职责不同、可独立测试。
- **`ui.js` 新增 `TensionGraph`**（canvas），沿用既有 `Fall` 的骨架——包括「用 setInterval 而非 rAF」这个刻意的选择：标签页被遮挡时 rAF 会被浏览器暂停，画面会就此冻结。
- 接线 `main.js`：演奏前 `setTarget(计划弧线)`，每小节 `push(实际张力)`，图例旁给出均值/跨度读数。
- 测试 76 → **83**（新 `test/tension.test.mjs`）。

## 为什么只做「显示」，不做「闭环」

设计文档里否决了「把张力喂回决策器」：它会同时改动候选与决策，正是第 2 轮花一整轮才稳住的部分；而且张力与 intensity 本身相关 0.45，接进反馈环有自激风险。**先让它可见，用眼睛判断它有没有决策价值，再决定要不要闭环**——比先接线再回滚便宜得多。

## 反思

- **两处失败不是测试写错，是我的语义假设错了**。① 空小节返回 0.077 而非 0——我原以为「缺字段取中性值」，但**没有音符就没有声音，也就没有张力**，不是中性。② 功能张力次序我写成 `T < Tp < S < D`，而表里是 `T .15 / S .45 / Tp .55 / D .85`——乐理上 `Tp`（bVI/bIII 这类相对调色彩和弦）听感比功能性下属和弦（IV/ii）更安定，它只是「颜色不同」而非「要往别处去」。**写下断言时暴露的是我脑子里的模型不完整，不是实现错了。**
- **原型顺手暴露了一个潜伏问题**：fixture 的 `intensity` 在 0 和 3 之间乱跳（`3.0 3.0 0.0 1.0 3.0`），因为 score 采样是整数档。张力曲线把它显式化了——这是**下一轮优化的天然靶子**，而如果没有这条曲线，它会继续潜伏。
- **「分析层」与「决策层」要物理隔开**。`tension.js` 里的 `FUNCTION_TENSION` 和 `candidates.js` 里的 `FN_NEXT` 是两张不同的表、两个不同的用途（前者衡量紧不紧，后者决定往哪走）。刻意不让它们共享代码——一旦共享，改分析权重就会悄悄改掉音乐。已经写进 AGENTS.md 的高危区。
- **脏输入必须降级而非抛错**。分析层跑在播放路径上，一个 `{notes: null}` 抛异常就会打断演奏（违反红线七）。已加测试覆盖 null/undefined/非数组/缺 midi 五种脏输入。
