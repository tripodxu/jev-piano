# 2026-10-25 · 性能轮 64：契合度缓存 + 护栏免展平 + 长会话状态上限（审计 P1/P2/D1/P3）

## 做了什么

审计性能项的修复。**领地**：`studio-roll.js`、`render.js`、`composer.js`、`player.js`、`ui.js` + 三份测试（studio-roll/composer/player）。

1. **P1 · 卷帘契合度缓存**：张力/非和声音之外的**第三份分析缓存**——逐小节 fit 要对每小节 filter 全部音符（O(bars×notes)），此前 hover 每次换小节重绘都重付一遍；现在 `fitCache` 随 `invalidate()` 作废（与另两份缓存同一入口，所有编辑路径本来就调它）。
2. **P2 · 护栏 avoid 免展平**：`mutateMelody` 新增 `softSet` 参数（直接传 Set 查 `.has`），composer 不再每次撞车都 `[...lastSigs, ...allSigs]` 展平成数组——长会话下（allSigs 数千条）这是每次护栏触发的白付 O(N)。`avoid` 参数保留（硬层 2 条，数组 `includes` 足够）。
3. **D1 · 长会话状态上限**：`SIG_MEMORY_CAP=2000`（软层指纹超限保留最近一半——连续即兴里几十分钟前的字面重复已不在听觉记忆里，忘掉无伤）+ `RECORDS_CAP=20000`（records 丢最旧，MIDI 导出覆盖最近演奏，比拖到 OOM 重要）。审计里 seenMel/seenLh/tensionGraph.meta 每小节只涨 1 条小对象，**有意不动**（记录在案）。
4. **P3**：`addDecision` 单次 innerHTML 赋值（此前赋值后又拼接再赋值，双解析）。
