# Jev 即兴钢琴（jev-piano）

> **Jev 每小节实时决策，边作曲边演奏的钢琴。** 你给一句话，它现场编曲、现场弹。
> 零框架、零构建、零运行时依赖的纯静态前端，一条 `wrangler deploy` 部署到 Cloudflare Workers。

架构参考 [cocktailpeanut/jevthoven](https://github.com/cocktailpeanut/jevthoven) 的"模型选、代码写"模式：**Jev**（TypeSafe 系统一模型）每小节一次请求、**七问并行**，从乐理合法的候选集里选出下一小节的**和声功能 · 和弦 / 左手织体 / 节奏型 / 旋律走向 / 强度 / 是否呼吸 / 旋律发展手法**；确定性代码把每个选择渲染成音符；Web Audio lookahead 调度器边决策边演奏。没有音频生成模型，没有隐藏曲库，每个音符都能溯源到一条决策。

```
一句话灵感 ──▶ LLM 扩写（可选，BYOK）──▶ 乐章计划（风格/调/速/曲式/弧线）
                                              │
                    ┌─────────────────────────┘
                    ▼
   ┌─────────── 每小节一次 Jev 请求（7 问并行）───────────┐
   │ state: 曲风/情绪/当前和弦/当前功能/近 4 小节/动机/弧线  │
   │ choice: 功能 · 和弦 · 左手织体 · 节奏 · 走向 · 发展手法│
   │ score: 强度 0-3        noul: 这小节要呼吸吗            │
   └──────────────────────┬─────────────────────────────┘
                          ▼
        确定性渲染内核：左手 11 种织体 + 旋律（和弦锚定/摇摆/人味）
                          ▼
        lookahead 调度器（提前 2 小节决策）──▶ Web Audio 合成钢琴
                          ▼
            键盘高亮 + 下落音符 + 和声功能轨 + 决策日志（功能/延迟/费用）
```

## 运行

### 本地（零配置即可玩）

```bash
python dev-proxy.py --port 8000     # 或 npm run dev
# 打开 http://127.0.0.1:8000 → 默认「离线随机」渠道，无需任何 key
```

无 key 时使用与真实 Jev **同构**的本地种子决策器（jevthoven 的 fixture 模式）：同一候选集、同一权重，确定性可复现。

### 部署到 Cloudflare Workers

```bash
npx wrangler login
npx wrangler deploy                 # npm run deploy
```

部署后 Jev 决策三种后端（自动探测，见 `src/worker.js`）：

| 后端 | 配置 | 特点 |
|---|---|---|
| **Workers AI**（默认） | `wrangler.toml` 里 `[ai]` 绑定（已开启） | 零 key，`@cf/typesafe/jev`，账号开箱即用 |
| TypeSafe 官方 | `npx wrangler secret put TYPESAFE_API_KEY` | 官方源，`jev-latest` |
| OpenRouter | `npx wrangler secret put OPENROUTER_API_KEY` | `typesafe/jev-1.13` |

LLM 扩写代理（可选）：`wrangler.toml` 里取消 `[vars]` 注释 + `npx wrangler secret put LLM_API_KEY`，或前端设置面板里用户自带 key 直连任意 OpenAI 兼容端点。

Worker 安全边界：`/api/llm` 只转发服务端 env 配置的端点（忽略请求体里的 baseUrl/apiKey，杜绝开放中继）；`/api/jev`、`/api/llm` 共享每 IP 限流（`RATE_LIMIT_PER_MIN`，默认 30 次/分钟，isolate 内存计数，多实例部署时为尽力而为）。

> 注意：TypeSafe 官方 API 不允许浏览器跨域直连（实测 CORS 拦截），所以**直连渠道仅适用于允许 CORS 的端点**；生产环境请走同源代理（本 Worker）。

## 成本（实测口径，2026-09-28 真实渠道复测）

- 每小节一次请求、**七问并行 + 九个和弦候选**：**~1860 input tokens ≈ $0.000078**（输出免费），一次 32 小节演奏 ≈ **$0.0025**
- 单条决策的载荷里 `questions` 占 **87%**（4084 / 4673 字符），`state` 只占 13%——`form`、`motif`、段落标志这些新增状态加起来不到 2%
- 决策延迟 0.4~2s，被"提前 2 小节"的决策管线完全藏住；速度 ≤140 BPM 时演奏不断流
- 离线随机渠道：$0

> ⚠️ **曾试图压缩提示词以省 token，实测不划算**：全面压缩后 token 降 5.5% 但真实渠道和弦种类从 10 掉到 6；把语义挪回 instructions 后质量只回到 7、token 优势只剩 0.8%。**这个配置对提示词措辞高度敏感——任何改写都会让真实输出移动 ±2 种和弦。** 现按「质量优先」保留原始措辞。
> 另注：同 seed 连续两次真实运行结果**完全一致**，说明该配置下模型实际是可复现的——所以上面的差异是真实差异，不是采样噪声。

## 两个界面

- **实时即兴**（默认）：边决策边演奏，不可预知，见下文全部说明。
- **工作室**（顶栏切换）：jevthoven 式"生成 → 编辑"工作流——输入灵感批量生成整曲（每小节仍由 Jev 逐小节决策，带进度条与取消，生成中即可预览已完成小节），然后在**钢琴卷帘**里编辑：
  - 点空白新增音 / 拖动移动 / 拖右缘改时长 / 双击删除 / Ctrl+Z·Ctrl+Y 撤销重做——全部**确定性编辑，不调用模型**（jevthoven 的 deterministic edits）
  - **卷帘自带时间轴**：头部自上而下是**张力曲线**（面积图）、**和声功能带**（主/下属/属/色彩四色）、和弦名，三者与音符区**共用同一个像素/拍刻度**，横轴天然对齐——看得出"哪一段音符密、那里张力高、那几小节在属功能上"
  - 回放支持循环、左右手分轨静音、BPM 调整、播放头跟随滚动
  - **让 Jev 修改**：自然语言（"左手更密集""整体轻一点"）由 Jev 从有限的确定性编辑命令中选择执行（加密/稀疏/移调/力度），对应 jevthoven 的 revisions routed through Jev；离线渠道用关键词匹配
  - 导出 MIDI 与项目 JSON，导入经校验（validated JSON import）；工作台自动存 localStorage，重开浏览器可恢复
  - 换一版 = 同一灵感新 seed 整曲变奏（jevthoven 的 whole-piece variation）

## 演奏中的控制（jevthoven 功能对齐）

- **演奏指示**（自然语言，实时生效）：输入框写"下一句左手更密集""结尾渐弱"，下一小节起 Jev 在 `director_note` 里读到并遵守；离线随机渠道用关键词近似响应。
- **暂停 / 继续**：挂起 AudioContext 冻结时钟，恢复后调度自动对齐，决策管线同步暂停。
- **移调**：开演前指定 12 个调性之一，否则由计划自动决定。
- **导出**：MIDI（SMF 双轨）与 WebM 录音随时可用。

## 和声功能层（候选集从哪来）

模型永远只在代码给的候选里挑（ADR-0001/0003），所以**候选集的来源决定了音乐的词汇量**。三层：

```text
music.js       调式音阶 → 全调内色板（带调式性质：小调 iiø、大调 viiø、dorian bVII）
candidates.js  四功能 T/S/D/Tp + 功能转移矩阵 + 声部进行加权
composer.js    Jev 第 7 问选「功能」，和弦仍在候选集内选
```

**候选全集 = 风格进行池 ∪ 调式全色板**。只有进行池时，romantic 小调只有 6 个根音，`unique_chords` 天花板约 6-8；并入色板后词汇随调式自动增长，而池内符号的既有权重与音色（jazz 的 `V7`/`ii7`）原样保留。

**声部进行加权**（可解释，取代纯拍脑袋的池计数）：

```text
smoothness = 共同音数 − 0.25 × 五度圈环形距离
```

共音越多、五度圈上越近，候选权重越高。**功能转移** `T→{S,D}`、`S→{D,Tp}`、`D→{T}`、`Tp→{D,T}`，乐句尾强制 `D→T`。

**第 7 问不做硬过滤**：同一请求里无法先问功能再问和弦，硬过滤会让模型自己的合法作答被前置问题判死。功能层真正起作用的三处——给模型语义语境、和弦作答非法时**回落到模型声明的功能族内**（比"取全局最高权重"聪明）、以及给 UI 一个比罗马数字更有意义的可读维度。

## 曲式（系统二 / 系统一的分工）

README 远期路线图第 3 条终于落地：**大模型负责曲式级规划（系统二），Jev 负责小节级选择（系统一）**。

`plan.sections` 是一组 `{id, arc, level, swing, bars, start}`——经典四段式 **A 陈述 → B 对比（全曲峰值）→ A' 再现 → Coda 收束**。LLM 可以给出自己的段落（提示词里是可选项），不合法就回退到按弧线派生的模板。

段落不是装饰：`intensityTarget` 改为**段落感知**——每段用自己的 `arc` 与 `level`，段内再走局部弧线。段落长度恒为乐句长度的整数倍，所以段落边界与乐句边界天然对齐。实测「实现张力 vs 段落目标」的相关性在四种弧线下全部提高（arch +33%、rise +54%、fall +10%、flat +16%）。

> **Coda 是收束，不是归零**：上升曲式的尾声仍比开场响——「庆典」收得比开场更轻是反直觉的。这条被既有测试守着。

**段落不只是动态的刻度**。段落边界在和声与动机上都有语义：新段落**从主和弦重新立足**（乐句可以半终止开始，新段落是一次重新开始），并且**重述主题**——`developCandidates` 在段落首把「承袭」权重 +1.6、把「新句」压到 0.3 倍。A→A' 的听觉关联正是靠"同一动机在新段落里再出现一次"建立的；没有这一步，两段只是并置而不是呼应。实测段落首的承袭率 **16.7% → 45.8%**（全局基线 12.2%）。同时 `state` 里的 `form` 字段让模型看到整条曲式（`A:flat@1.2 B:rise@1.9 …`）——它不知道下一个段落是再现还是对比，就谈不上呼应。

**曲式在界面上是可见的**，而且**不依赖颜色**：计划卡列出一行纯文本清单（`曲式 A 8 小节 · B 8 小节 · A' 8 小节 · Coda 8 小节`），功能轨与张力带在段落边界画**虚线竖线 + 段落名**，钢琴卷帘头部同样画出。这样在灰度或色觉障碍下曲式依然可读——曲线标注不能只靠颜色，这是数据可视化的基本约束。

## 反重复设计（量化验证）

`node scripts/analyze-repetition.mjs 32 2026 random [--real]` 输出重复度指标。修复前 → 修复后（fixture，4 种子均值）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 旋律音程熵 | 2.2 | 2.4-2.8 |
| 跳进占比（≥5 半音） | 4-9% | 8-21% |
| 左手唯一小节 | 15-18/32 | 26-28/32 |
| 和弦种类 | 6（4 和弦循环） | 8-10 |
| 相邻小节字面重复 | 偶发 | 0 |

六层机制：

1. **旋律指纹护栏**：与最近两小节指纹（onset+绝对音高）撞车时，依次尝试整句升/降一个音级、加经过音、倒影、**节奏压缩**、音高扫掠，直到避开**全部**已存指纹；变形后仍检查，防止修东墙塌西墙。乐句尾的末端锚定发生在护栏**之内**（护栏在最终形态上判定），否则"逃出去又被锚定改回撞车"。左手有同构护栏（撞车就重渲染换一个变体）。
2. **发展手法**（第 7 问）：承袭/模进/倒影/装饰/新句，以上一小节素材为原料（motif development）。
3. **左手织体逐小节变体**：每种织体带重击/呼吸空拍/方向翻转/色彩换位/经过音/音区抬升变体；同一和弦不再弹出同一小节。
4. **节奏变奏**：Jev 选"性格"，内核每小节位移/补弱位/删音/整体切分位移。
5. **旋律跳进 + 时长人味**：20% 概率 ±6~12 半音真跳进；音符时长 ±15% 人味，不再等长机械。
6. **音区漂移**：锚点中心随机游走 + 1/4 乐句整体换音区。

和声层三件套：

- **根音疲劳断路器**：每个根音疲劳值随使用累计、随时间衰减（×0.93），超阈值（2.0）的根音**从候选集中剔除**（含替换和弦）；三和弦循环最多维持 6 小节必被强制打断，模型被迫走 bIII/bVI/bVII/副属的新领域。
- **循环锁死断路器**：最近 6 小节的根音只剩 ≤3 个不同值即判定"正在绕圈"，把**循环成员**（窗口内出现 ≥2 次的根音）当小节剔出候选。与疲劳互补：疲劳是"用得太多"、攒得慢，锁死是"结构上正在绕圈"、当小节生效。实测它把真实渠道开头 7 小节的 `Cm-Fm-G` 字面循环从第 7 小节就打断（见下表）。
- **候选集强制**：模型答案不在候选集内（含用标签作答、报被排除和弦）一律拒绝，回落最高权重候选——非法着法不可表示。
- **替换和弦与乐句轮换**：副属/借用 iv/7sus4 悬挂/导七进入候选；乐句开头鼓励换进行起点；连续同和弦按池数放大罚分。

真实 Jev 渠道实测（`--real`，32 小节，seed 2026/2027，约 $0.005/组）：

| 指标 | 第 2 轮（断路器接线后） | 第 13 轮（色板+曲式+动机发展之后） |
|---|---|---|
| 和弦种类 | 7 / 7 | **10 / 8** |
| 旋律唯一小节 | — | 29 / 28 |
| 左手唯一小节 | 30 / 29 | 26 / 29 |
| 相邻字面重复（旋律/左手） | 0 / 0 | **0 / 0** |
| 候选集驳回 / 断路器触发 | — | 0 / 4 |
| 兜底命中（真实渠道失效） | 0 | **0** |

> 注：所有硬不变量（相邻字面重复 = 0、播放不断流）在真实渠道全部守住。**同 seed 连续两次真实运行结果完全一致**，说明该配置下模型可复现——真实渠道的数字是真实差异，不是采样噪声。

## 设计说明

- **决策透明**：每小节在"Jev 的实时决策"面板展示选择、置信度、延迟、tokens 与费用——每个音符可溯源。
- **张力对照带**：演奏记录区顶部一条曲线，实线是**实际张力**、虚线幽灵是**计划弧线**。张力由五个分量加权：和弦音程的不协和度（半减七 `iiØ` 最高、三和弦最低）、和声功能（属 > 下属 > 色彩 > 主）、音域跨度、节奏密度、力度。别的 AI 音乐生成器给你音频，这里给你**和声轨迹**——你能看着 Jev 一小节一小节把曲子的形状走出来，也能看出它在哪儿偏离了自己的计划。
- **动机卡**：主题第一次响起时（第 2 小节），把它的旋律轮廓画成一条曲线——曲子的「形状」，并累计它**回来了几次**。别的 AI 音乐生成器给音频，这里给可溯源的结构。功能轨上每小节还标着发展手法（承/模/倒/装）：「承」带**顶部括线与亮边**，表示主题又回来了。
- **和声功能轨**：和弦区下方一条横向色带，每小节一格按和声功能着色（主=黄铜 / 下属=冷青 / 属=猩红 / 色彩=旧金），随演奏推进。断路器直接画在格上——顶部细刻线表示"循环锁死断路器在这一小节切了一刀"，右端缺口表示"模型答案越界被候选集驳回"。
- **永不中断**：真实 Jev 不可用（无 key / CORS / 断网 / 超时 10s）时，同构 fixture 决策器无缝接管，UI 标注"兜底"。
- **动机统一**：第 2 小节的旋律被记为**动机**（音高序列 + 节奏网格 + 走向）。之后每小节 Jev 通过发展手法决定它与动机的关系——**承袭**（在新的和声里重述动机，强拍锚到当前和弦但**本来就在和弦里的音不动**）、**模进**（把刚才那句移一个音级）、**倒影**（把刚才那句镜像）、**装饰**（给刚才那句加经过音）、**新句**（唯一真正从零开始的手法）。实测承袭小节与动机的平均音程差 **3.76 → 0.87 半音**——主题真的会回来。
- **动态连续**：Jev 的强度问按 API 契约只能答 0-3 整数档，但音乐需要连续动态。直接渲染整数会让相邻小节平均跳 1.03 档、26.9% 的跳变 ≥2 档（力度 2.4 倍落差 + 左手织体同时翻转）。现在把整数回答解释为「**相对计划弧线的偏移**」（模型保留一半发言权），再施加每小节 **1 档的速率限制**——模型仍决定去哪里，只是不能一小节跳三档。实测：平均跳变 1.03→0.49，跳 ≥2 档 26.9%→**0%**。
- **和声安全**：候选集只含本调罗马数字与终止式加权（乐句尾 V/I 加权 1.0、进行池延续 +1.2），非法和声不可表示。
- **拼写正确**：和弦按乐理拼写显示——降号侧音级恒用降号名（C 小调的 bVI 显示 `Ab`、bVII 显示 `Bb`、bIII 显示 `Eb`）。注意与琴键名的分工：琴键的物理键名保持升号（钢琴上没有 Ab 键），和声记谱才用降号。
- **音色**：默认合成钢琴（三角波+两枚正弦泛音+包络+低通+生成式混响），零下载即开即响；升级路线：@tonejs/piano（Salamander 采样，数 MB）。

## 远期路线图：从钢琴到乐团
